# Hackathon brief: VAE Synth

One page to get back up to speed. Details live in the linked docs.

## The pitch

**Describe a sound, get a playable, editable synth preset.** Not a sample: a
real patch on a real synth, with knobs you can keep turning.

Two routes to the preset, both ending in the same 93-control vector:

1. **Generative (the VAE).** prompt → latent[8] → trained decoder → 93 controls → synth.
   Needs the student's trained decoder.
2. **Retrieval (the backup, works today).** reference audio → find the closest
   presets in a rendered bank → top 5 editable presets with WAV previews.
   Planned front end: Stable Audio Small turns a prompt into the reference audio.

```
                ┌── PromptEncoder ─► latent[8] ─► ONNX decoder ─► features[191] ─┐
prompt ─────────┤                                                                ├─► controls[93] ─► Lite / Surge engine
                └── Stable Audio* ─► reference.wav ─► search bank (mel or SAME) ─┘
                                                     * not built yet
```

## Numbers worth quoting

From the 3,561-preset comparison run (medians):

| | Lite vs Surge (engine gap) | Original vs vector (schema loss) |
|---|---|---|
| spectrum over time | **3.5 dB** (was 4.9) | 11.5 dB |
| loudness | **1.2 dB** (was 4.0) | 6.7 dB |
| brightness | 0.15 oct | 0.79 oct |
| envelope correlation | 0.96 | 0.80 |

**The story:** our permissive Lite engine is now about 3× closer to Surge than
the schema is to the original presets. So the bottleneck is the schema (what
93 controls can express), not our DSP. Rough guide: under 2 dB very close,
2–5 dB same kind of sound, over 8 dB clearly different.

Quality checks done: ASan and TSan clean on all test suites; pluginval
strictness 5 passes on the VST3 and AU (auval included).

## Methods, in one line each

- **Dataset:** Surge factory + third-party presets, converted by the importer. Modulation that opens a muted osc or zero sustain is folded into the static value so presets don't import silent. Noise channel goes into a free osc slot.
- **Model target:** a VAE over the 191 features; one-hot in, argmax out for categoricals.
- **Engine matching:** measure, don't copy. Lite constants (osc levels, noise hold rate, FM index, filter resonance) were fitted from rendered audio, not Surge code.
- **Retrieval baseline:** handcrafted distance = mel spectrum RMS / 20 dB + 0.5 × envelope RMS. Heuristic weights, not calibrated.
- **Retrieval learned:** frozen SAME-S encoder, pooled stats, cosine. Not trained for synth knobs, so it's a hypothesis to test by ear.
- **Evaluation:** listen to top-5 from both methods on the same isolated notes; judge timbre, envelope, playability separately. A self-query recovering its source only proves the wiring.

## Demo script (works today, no trained model)

1. Pick an isolated note: pluck, bell, bass or simple pad. Avoid sequences, speech, full mixes.
2. `vae_retrieve search factory-bank.json reference.wav out/` (and/or `same_search.py search ...`).
3. Open the plug-in, **Preset...** → `out/match-1.json`, play it on the keyboard.
4. Turn a knob to show it's a real patch, not a sample.
5. Optional: the listening report HTML to show both methods side by side.

Pre-built in `build-lite-au/`: `factory-vectors.jsonl`, `factory-bank.json`,
`same-audio/`, `same-evaluation-references/`. Commands in
[RETRIEVAL.md](RETRIEVAL.md) and [SAME-RETRIEVAL.md](SAME-RETRIEVAL.md).

## Open decisions (mostly the student's)

1. **Modulation routing.** Currently provisional: one route per modulator (FEG, LFO1, LFO2). Options: (a) keep that, (b) fixed depth-only routes, e.g. LFO1/2 → pitch, cutoff 1/2, volume, pan, (c) N (source, dest, depth) slots. Data: LFO1 → pitch is by far the most common (199 presets), 179 presets have more than one LFO1 route.
2. **Wavetable position.** Schema has "wavetable" as one wave option with no table or position, so both engines play one fixed table. Proposal: a real multi-frame table plus a `wt_position` control (93 → 94) imported from Surge's Morph, later a mod destination.
3. **Latent prior.** Random draws uniform ±1; a standard VAE expects N(0, 1). One-line change in `PluginProcessor::generateRandom` + state the prior in the decoder contract. Agree with whoever trains the model.
4. **Prompt encoder.** Currently a hash stub. Real one: CLAP or a sentence embedding + projection into the 8-d latent.

## Things that will come up

- **"Random only changes knobs, never waveforms or FX."** That's the stub decoder: its biases (±6.9) swamp the random push (±0.9). A trained decoder flips choices normally. To make Random meaningful before then: clip `eps` at ~0.25 in [models/make_stub_decoder.py](../models/make_stub_decoder.py) and regenerate. Not done.
- **"Will the trained decoder be correct?"** Plausible, not exact. It inherits the dataset's habits (mostly effects off, saw/wavetable) and the 11.5 dB schema loss.
- **"Can it load Surge presets?"** Only via the offline converter. No in-plug-in `.fxp` import yet.
- **"Does retrieval invent new sounds?"** No, it finds the nearest existing preset. A bounded parameter-refinement step after retrieval is the natural next idea (not built).
- **Licensing.** Default build has no Surge code. The Surge build is GPL: fine locally, don't ship it. Don't bundle Surge factory presets in the Lite build. JUCE is AGPL/commercial. See [LICENSING.md](LICENSING.md).

## Still open on the engine side

Attack timing (rank agreement only 0.46) and effects (distortion 7.6 dB, mod FX
5.5, delay 4.8, chorus 4.7, reverb 4.4). Category classifier test is too weak
to read anything into; swap in CLAP embeddings. Full list:
[FIXES-lite-vs-surge.md](FIXES-lite-vs-surge.md).
